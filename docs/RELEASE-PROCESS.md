# دليل دورة الإصدارات والنشر (Release Process)

يوثق هذا الدليل استراتيجية الإصدارات وسير العمل المعتمد في مستودع **WDS** لإنتاج حزم التثبيت الرسمية لنظام Windows وإتاحتها للمستخدمين عبر GitHub Releases.

---

## 🌲 استراتيجية الفروع (Branching Strategy)

- `develop`: فرع التطوير والتكامل المستمر. تُنفذ عليه اختبارات الـ CI تلقائياً عند كل Push.
- `main`: فرع الإصدارات المستقرة فقط. لا يُقبل فيه التعديل المباشر، بل عبر Pull Request بعد اجتياز فحص الـ CI.
- `feature/*`: فروع الميزات الجديدة (تتفرع من وتندمج في `develop`).
- `fix/*`: فروع الإصلاحات العاجلة.

---

## 🏷️ الترقيم الدلالي للإصدارات (Semantic Versioning)

نتبع نظام الترقيم الدلالي `MAJOR.MINOR.PATCH`:
- **MAJOR:** تغييرات بنيوية أو معمارية كبرى تكسر التوافق السابق.
- **MINOR:** ميزات جديدة متوافقة مع الإصدارات السابقة (مثل إضافة دعم لمنصة جديدة).
- **PATCH:** إصلاحات برمجية وتحسينات في الأداء والاستقرار.

---

## 🚀 خطوات إطلاق إصدار جديد (Release Workflow)

1. **التحقق المحلي واجتياز بوابات الجودة:**
   تأكد من نجاح اختبارات Lint وBuild وCargo Tests وعزل الجلسات محلياً.

2. **تحديث رقم الإصدار:**
   يتم تحديث رقم الإصدار في الملفين:
   - `package.json`
   - `src-tauri/tauri.conf.json`

3. **الدمج في فرع `main`:**
   دمج فرع `develop` المحدث إلى `main`.

4. **إنشاء Tag الإصدار:**
   إنشاء Tag مسبوق بحرف `v` ودفعه إلى المستودع:
   ```powershell
   git tag v1.0.0
   git push origin v1.0.0
   ```

5. **البناء الآلي عبر GitHub Actions:**
   بمجرد دفع الـ Tag، يبدأ سير العمل الآلي `.github/workflows/release.yml`:
   - بناء مثبت Windows بصيغة NSIS (`.exe`).
   - توقيع حزمة التحديث التلقائي رقمياً بمفتاح Minisign المخزن في GitHub Secrets.
   - إنشاء ملف `latest.json` الذي يقرأه تطبيق WDS للتحقق من التحديثات.
   - حساب تجزئات SHA-256 لجميع الملفات ونشر الإصدار كـ GitHub Release رسمي.

---

## ⏪ خطوات استعادة إصدار سابق (Rollback Procedure)

في حال حدوث خلل حرج في إصدار منشور:
1. حذف الـ Release أو تعيينه كـ Prerelease لمنع المستخدمين من تنزيله تلقائياً.
2. إنشاء إصدار تصحيحي جديد برقم أعلى (مثلاً `v1.0.1`) يحتوي على الإصلاح أو يعيد الشيفرة إلى حالة الإصدار السابق المستقر.
3. دفع Tag الجديد ليقوم الـ Auto-Updater بتحديث الأجهزة المثبت عليها التطبيق تلقائياً إلى الإصدار التصحيحي.
